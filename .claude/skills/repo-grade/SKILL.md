# repo-grade — 저장소 AI‑Ready 채점관
이 저장소가 AI 협업(Claude Code 등)에 얼마나 준비되어 있는지를 100점 만점(5개 카테고리 × 20점)으로 엄격하게 채점한다.
**점수를 후하게 주지 않는다.** 근거 없이 만점을 주지 말고, 실제 파일을 열어 확인한 내용만 근거로 삼는다. 확인하지 못한 항목은 감점한다.

## 실행 절차
1. 저장소의 실제 파일을 확인한다 (추측 금지):
  - `index.html` (또는 진입점 파일) 존재 여부와 구조
  - `CLAUDE.md`, `GOLDEN_RULES.md` 등 규칙 문서
  - `.claude/agents/`, `.claude/skills/` 하위 서브에이전트·스킬 설명
  - `.claude/settings.json`, hooks 스크립트
  - 최근 커밋/워크로그 등 문서와 코드의 최신성을 판단할 단서
2. 아래 루브릭 표에 따라 카테고리별로 0 / 10 / 20점 중 하나를 매긴다.
3. 출력 형식대로 표 + 총점 + ROI 우선순위 개선안 3가지를 작성한다.

## 채점 루브릭
| 카테고리 | 0점 | 10점 | 20점 |
|---|---|---|---|
| (A) 길 안내<br>진입점·핵심 파일 안내 | 진입점이 어디인지 문서에 언급이 없다 | 진입점은 언급되나 핵심 파일 간 관계·역할 설명이 부족하다 | 진입점, 핵심 파일, 각 파일의 역할이 명확히 안내되어 있다 |
| (B) 규칙 문서 품질<br>CLAUDE.md 간결성/명확성 | CLAUDE.md가 없거나, 있어도 35줄을 크게 초과하거나 명령·금지사항이 불명확하다 | CLAUDE.md는 있으나 35줄 초과이거나, 명령/금지사항 중 일부만 명시되어 있다 | 35줄 이내로 간결하고, 명령·금지사항이 구체적이고 실행 가능하게 적혀있다 |
| (C) 숨겨진 규칙 문서화<br>Why/Gotcha 기록 | 왜 이렇게 만들었는지, 함정(Gotcha)이 무엇인지 어디에도 기록이 없다 | 일부 규칙에 이유가 붙어있으나 함정·예외 상황 기록은 없다 | 왜 그런 제약이 있는지, 흔히 실수하는 부분(Gotcha)이 문서 곳곳에 구체적으로 기록되어 있다 |
| (D) 검증 게이트<br>브라우저 수동 테스트 / page‑checker | 변경 사항을 어떻게 검증해야 하는지 아무 안내가 없다 | 검증 방법이 언급은 되나 구체적 절차나 기준(등급 체계 등)이 없다 | 브라우저 수동 테스트 절차 또는 page‑checker 같은 점검 서브에이전트가 구체적 기준(🔴🟡🟢 등)과 함께 명시되어 있다 |
| (E) 문서 신선도<br>문서‑코드 일치 | 문서 내용이 현재 코드 상태와 명백히 다르거나 오래된 정보를 담고 있다 | 대체로 일치하나 일부 항목이 최신 코드 상태를 반영하지 못한다 | 문서 내용이 현재 코드 구조·기능과 정확히 일치한다 |

## 출력 형식
다음 순서로 출력한다:
1. 표: `카테고리 | 점수 | 근거 | 개선 제안` (5행)
2. 총점: `총점: XX / 100`
3. ROI 우선순위 개선안 3가지 (적은 노력으로 점수를 많이 올리는 순서대로, 각 항목에 예상 효과 명시)

## 규칙
- 실제 파일을 열어 확인한 뒤에만 점수를 매긴다. 확인하지 않고 추측으로 점수를 주지 않는다.
- 각 카테고리 점수는 반드시 0 / 10 / 20 중 하나로만 매긴다 (중간값 없음).
- "근거" 칸에는 어떤 파일의 어떤 내용을 보고 판단했는지 구체적으로 적는다.
- 이 프로젝트는 순수 정적 `index.html` 이며 `package.json`, `npm test`가 없다.
  검증 게이트(D)는 `npm test`가 아니라 브라우저 수동 테스트 또는 `page‑checker` 서브에이전트
  기준으로 평가한다.
